# سامانه مدرسه طاها — نسخه یکپارچه PHP/MySQL

این نسخه، ظاهر بازطراحی‌شدهٔ سایت طاها را نگه می‌دارد و ورود و کنترل دسترسی را به API سمت سرور منتقل می‌کند. برای اجرای واقعی به هاست دارای **PHP 8.1+، MySQL/MariaDB، PDO MySQL و افزونه mbstring** نیاز دارد. GitHub Pages برای این نسخه مناسب نیست، چون PHP اجرا نمی‌کند.

## امکانات پیاده‌سازی‌شده

- ورود مشترک دانش‌آموز، معلم و مدیر اصلی با نام ورود و رمز.
- کلاس دانش‌آموز از حساب خودش تعیین می‌شود؛ انتخاب آزادانهٔ کلاس قبل از ورود حذف شده است.
- دانش‌آموز فقط برنامه و کارهای کلاس ثبت‌شده در حساب خودش را می‌خواند و امکان نوشتن ندارد.
- معلم فقط کلاس‌های scope شده را می‌بیند؛ برنامهٔ درسی فقط برای درس‌های تخصیص‌یافته‌اش نمایش داده می‌شود. دسترسی نوشتن/ویرایش/حذف نیز در API بررسی می‌شود.
- مدیر اصلی به همهٔ کلاس‌ها دسترسی دارد و می‌تواند حساب دانش‌آموز و معلم بسازد، حساب را فعال/غیرفعال کند و رمز را بازنشانی کند.
- ساخت گروهی حساب دانش‌آموز از فهرست نام‌ها (هر نام در یک خط)؛ برای هر دانش‌آموز رمز اولیهٔ جدا ساخته می‌شود.
- اختصاص چند محدودهٔ پایه/رشته/شعبه/درس به یک معلم.
- رمزها با `password_hash()` ذخیره می‌شوند؛ رمز خام فقط در پاسخ ساخت یا بازنشانی همان لحظه نمایش داده می‌شود.
- همهٔ نقش‌ها می‌توانند رمز خودشان را تغییر دهند.
- برنامهٔ هفتگی و کارهای روزانه هر ۳۰ ثانیه برای تازه‌سازی تغییرات سرور بررسی می‌شوند؛ ساختار ظاهری صفحه‌های اصلی حفظ شده است.

## نصب روی هاست

1. محتوای این پوشه را در ریشهٔ دامنه یا یک پوشهٔ سایت روی هاست لینوکس آپلود کنید.
2. در کنترل‌پنل هاست یک دیتابیس MySQL و یک کاربر با دسترسی کامل به همان دیتابیس بسازید.
3. فایل `schema.sql` را در phpMyAdmin یا خط فرمان روی دیتابیس اجرا کنید.
4. فایل `api/config.example.php` را به `api/config.php` تغییر نام دهید و اطلاعات دیتابیس را وارد کنید.
5. در همان فایل، `bootstrap_admin_login` و `bootstrap_admin_password` را تغییر دهید. مقدار رمز نباید همان متن نمونه باشد؛ یک رمز طولانی و یکتا انتخاب کنید. شناسهٔ ورود مدیر همان `bootstrap_admin_login` است (نمونهٔ پیش‌فرض: `admin`).
6. مطمئن شوید HTTPS فعال است. در HTTPS کوکی نشست به‌صورت Secure و HttpOnly تنظیم می‌شود.
7. وارد سایت شوید با شناسه و رمز مدیر که در مرحلهٔ قبل تعیین کرده‌اید. اولین درخواست API، حساب مدیر اصلی را در صورت خالی بودن جدول مدیران ایجاد می‌کند.
8. از پنل مدیر، حساب معلم‌ها و دانش‌آموزها را بسازید. اطلاعات رمز اولیه را همان لحظه به افراد مربوط تحویل دهید.

**مهم:** فایل `api/config.php` را منتشر یا برای کسی ارسال نکنید. فایل نمونه عمداً رمز واقعی ندارد. از پوشهٔ `api/.htaccess` برای مسدودکردن دسترسی مستقیم به فایل تنظیمات در Apache استفاده شده است؛ اگر وب‌سرور Nginx است، قانون معادل deny برای `api/config.php` را در تنظیمات Nginx قرار دهید.

## ورود و نقش‌ها

- مدیر اصلی: شناسه‌ای که در `api/config.php` تعیین کرده‌اید.
- دانش‌آموز: نام و نام خانوادگی؛ رمز تصادفی که هنگام ساخت گروهی تولید می‌شود.
- معلم: نام و نام خانوادگی؛ همین نام، شناسهٔ ورود داخلی اوست و شناسهٔ جداگانه‌ای در فهرست معلم‌ها نمایش داده نمی‌شود.
- همهٔ رمزهای اولیه حداقل ۱۰ نویسه دارند و بعد از ورود، کاربر می‌تواند رمز را از بخش تغییر رمز عوض کند.

## انتقال داده‌های قدیمی Firestore

این بسته به Firestore متصل نیست و از قواعد باز قبلی استفاده نمی‌کند. داده‌های قبلی Firestore **به‌صورت خودکار منتقل نمی‌شوند**. اگر می‌خواهید برنامه‌ها و کارهای قبلی را نگه دارید:

1. از مجموعه‌های `lessons` و `tasks` خروجی JSON نرمال‌شده تهیه کنید.
2. فایل JSON باید این ساختار را داشته باشد:

```json
{
  "lessons": [{"group":"دهم ریاضی شعبه 1","day":"شنبه","dayOrder":1,"time":"08:00 - 09:30","timeOrder":480,"name":"ریاضی","teacher":"نام معلم"}],
  "tasks": [{"group":"دهم ریاضی شعبه 1","day":"شنبه","dayOrder":1,"title":"تمرین","desc":"صفحه ۱۰"}]
}
```

3. فایل را روی سرور نگه دارید و از خط فرمان اجرا کنید:

```bash
php migration/import-firestore-json.php /path/to/export.json
```

این ابزار فقط از CLI اجرا می‌شود و درج را در تراکنش انجام می‌دهد. ابتدا روی نسخهٔ پشتیبان دیتابیس آزمایش کنید.

## محدودیت‌های فعلی و موارد نیازمند بررسی روی هاست

- بخش «فایل‌ها» همچنان جایگاه نمایشی/آماده‌سازی است؛ آپلود، دانلود و مجوز فایل‌ها در این نسخه پیاده‌سازی نشده است.
- داده‌های قدیمی Firestore تا زمان اجرای انتقال دستی بالا در دیتابیس جدید ظاهر نمی‌شوند.
- این محیط اجرای PHP به درایور PDO-MySQL و دیتابیس واقعی دسترسی نداشت؛ بنابراین فایل‌های PHP از نظر syntax بررسی شده‌اند، اما آزمون یکپارچهٔ ورود، نشست، تراکنش و مجوزها باید پس از نصب روی هاست با دیتابیس آزمایشی انجام شود.
- بعد از نصب، حتماً با حساب آزمایشی دانش‌آموز و معلم تلاش کنید شناسهٔ کلاس یا درس خارج از محدوده را از API بخوانید/ویرایش کنید؛ پاسخ مورد انتظار HTTP 403 است.

## ساختار فایل‌ها

- `index.html`, `style.css`, `app.js`, `school-config.js`: رابط بازطراحی‌شده و منطق مرورگر
- `api/auth.php`: ورود، نشست، خروج و تغییر رمز
- `api/users.php`: ساخت و مدیریت حساب‌ها (فقط مدیر اصلی)
- `api/data.php`: خواندن و تغییر برنامه/کارها با کنترل دسترسی سمت سرور
- `api/common.php`: نشست، اتصال دیتابیس، CSRF و توابع مجوز
- `schema.sql`: جداول کاربران، محدوده‌های معلم، برنامه و کارها
- `migration/`: راهنمای انتقال داده‌های قدیمی
